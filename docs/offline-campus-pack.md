# Offline campus pack

The campus pack is a versioned snapshot of the campus catalog and walking graph. It includes building outlines and coordinates, indoor location names and search terms, plus route nodes, active pathways, allowed walking modes, and pathway shape points. `/campus/pack/manifest` declares schema compatibility, a content hash, byte size, and the catalog file URL. The client streams the file, checks its size and SHA-256 checksum, parses the catalog and graph, and then replaces the prior saved copy in one preference write. A failed download or incompatible manifest leaves a usable saved copy intact.

Android stores the pack through `shared_preferences`; web stores it in browser local storage. The app checks the saved hash on every load. Browser storage can be evicted, so a missing or corrupt pack returns the UI to its download state. Web app shell assets are cached by `web/campus-sw.js`; the first successful online visit must finish installing that worker before an offline reload can open the app.

The pack supports an offline vector campus map with building outlines and walking pathways, building and indoor location search, destination selection, and shortest or shaded walking routes computed on-device. The app suppresses tile requests when the device reports no network connection. Street and satellite raster imagery remain remote services and are not bundled. Online route requests still use `/campus/routes` when there is no usable saved graph; with the current pack, routes are computed locally from the saved graph. The manifest reports `mapTiles: false` and `routing: true` to distinguish remote imagery from offline route data.

To verify manually: install the campus pack while online, then enable airplane mode and open the map. Confirm that building outlines and pathway lines remain visible, choose a destination and a campus or gate origin, and confirm shortest and shaded routes render without a connection. The offline banner should identify the vector map and explain that satellite imagery is unavailable. On web, the service worker must first activate during an online visit so the app shell can load after an offline reload. Reconnect to check for a newer pack or update. Deleting the pack should remove the offline entry on the next app open.
